# 短程线网壳的参数化建模：几何、方法，与一次脚本重构

短程线网壳（geodesic shell）的参数化建模脚本，我前后改过好几版。最早那版是在本科时跟着导师的项目写的，做的是基于 Python 的 ABAQUS 二次开发——那时刚接触 ABAQUS 和 Python，回头看确实有点稚气。后来把它重新拆了一遍：几何算两遍的问题解决了，顺带把当时没想明白的地方也补上了。这篇就是这个项目从头到尾的一份记录。

## 它是什么

短程线网壳是一种以球面为基准的单层或双层空间网格结构，杆件沿球面上的短程线（测地线）方向布置。这个形态最早由美国建筑师 R. Buckminster Fuller 在二十世纪中叶系统化提出并推广，所以也常被叫作 Geodesic Dome。

从几何上看，它是把正多面体（通常取正二十面体）的各个面在球面上继续细分，再把细分出来的节点投影到外接球面上，最后连线成三角网格。

### 几何原理

**基础多面体。** 最常用的母体是正二十面体（Icosahedron）：

- 20 个正三角形面
- 12 个顶点
- 30 条棱
- 每个顶点周围汇聚 5 个三角形（五重对称）

在所有正多面体里，正二十面体最接近球面，是短程线网壳天然的起点。

**频率（frequency）细分。** 每个三角形面按频率 v 做均匀细分（也译作「分频」或「阶数」）。频率越高网格越密，结构越接近理想球面，杆件长度的离散种类也越多：

| 频率 | 每个面细分为 | 整个球面总三角形数 |
| --- | --- | --- |
| 1V | 1 | 20 |
| 2V | 4 | 80 |
| 3V | 9 | 180 |
| 4V | 16 | 320 |
| nV | n² | 20n² |

**投影到球面。** 细分产生的节点起初落在正二十面体的平面三角形上，需要沿从球心引出的径向投影到外接球面。这一步会引入不同长度的杆件——平面上等分出来的弧段，投到球面上就不再等长了。

## 细分到球面的四种方法

把正二十面体细分开到球面上，方法不止一种。不同方法得到的杆件长度分布、节点拓扑、对称性都不一样，工程上按跨度、施工条件和外观需求来选。

### 弦分法（Chord / Alternate Method）

最常用，也是本项目脚本采用的方法。

步骤：

1. 取正二十面体的一个等边三角形面
2. 把三条边各自等分为 f 段（f 即频率），每条边上得到 f+1 个节点
3. 用平行于三条边的直线段把三角形内部分成 f² 个小三角形，共产生 (f+1)(f+2)/2 个内部节点
4. 所有节点沿径向投影到外接球面
5. 相邻节点用杆件相连

特点是节点计算简单，只涉及线性插值与一次球面投影；同一频率下杆件长度种类较少（通常 f 种以内），便于构件标准化；五重、三重、二重对称性完全保留。投影后杆件并不是真正的测地线，但长度接近，工程上足够精确。

### 短程线法（Geodesic / Great-Circle Method）

严格意义上的短程线方法。先对正二十面体三角形的三条边投影到球面，得到三段大圆弧；再把每段大圆弧等角分割为 f 份；最后用球面大圆连接分割点，在三角形内部形成更小的球面三角形网格。

杆件严格沿大圆（测地线）方向，受力最合理；节点完全位于球面上，不需要二次投影。代价是内部节点的球面几何计算较复杂，涉及球面三角解算，杆件长度种类也比弦分法稍多。

### 纬线法（Parallel Method）

适用于旋转对称优先的场合。按固定纬度角把球面切成若干水平环，在每条纬线上等角布点，相邻纬线上的节点用径向与斜向杆件连接。

几何最简单，易于手工绘制，节点在同一纬度上完全规则，施工放线方便。但三角形在极点附近明显变形（狭长），靠近赤道又过于扁平，杆件长度种类多、标准化程度低——而且它并不是真正意义上的短程线网壳。

### Kenner 分类

Hugh Kenner 在 *Geodesic Math and How to Use It* 里把球面细分归纳成三类：

- **Class I**：细分线平行于原多面体边，即上面说的弦分法
- **Class II**：细分线垂直于原多面体边（也叫 Triacon 法），节点落在原边的中垂线上
- **Class III**：细分线斜交于原多面体边，形成不对称的旋转手性网格

Class I 杆件种类最少、对称性最直观，是工程实践里最主流的选择。

### 方法对比

| 方法 | 杆件长度种类 | 节点计算复杂度 | 对称性 | 典型应用 |
| --- | --- | --- | --- | --- |
| 弦分法 (Class I) | 少 | 低 | 高 | 一般穹顶、工业建筑 |
| 短程线法 | 中 | 高 | 高 | 要求严格受力贴合的大跨 |
| 纬线法 | 多 | 最低 | 仅绕轴对称 | 小型穹顶、罩棚 |
| Class II | 中 | 中 | 高 | 美学外观要求的建筑 |
| Class III | 多 | 高 | 手性对称 | 艺术化造型 |

## 为什么这种结构好用

- **受力合理。** 球壳以薄膜应力为主（压为主、弯矩小），短程线方向的杆件恰好贴合主应力流线，材料利用率高。
- **跨度大、自重轻。** 结构效率高，经济跨度可以做到 50–200 m 以上，自重常低于同跨度的传统结构。
- **模块化施工。** 杆件长度和节点类型的种类有限，尤其是同一频率下，便于工厂预制与现场装配。
- **几何冗余度高。** 多向杆件形成的三角网格在力学上是几何不变体系，抗风、抗震性能良好，局部失稳通常不会引发整体失效。

常见的工程应用有体育场馆、展览馆与温室（如蒙特利尔世博会美国馆、伊甸园工程 Eden Project），雷达天线罩与观测台，水厂、筒仓这类工业储罐顶盖，以及应急避难所和军用穹顶。

## 一次重构

两套脚本能共用几何，不是一开始就这么写的。第一版能跑，但有两处几乎一样的几何计算——一处用来搜索最优分角，一处用来真正建模。任何几何改动都得同步改两个地方，漏一次就是几个小时的排查。

### 原来的问题

原脚本 450 行，核心结构是这样：

| 函数 | 行数 | 干什么 |
| --- | --- | --- |
| `xyz_coordinates` | 27 | 把点缩放到球面 |
| `search_best_adc` | 175 | 复制了一遍 `part()` 的坐标计算，只为算杆长方差 |
| `part` | — | 又算一遍同样的几何，然后连成线 |

`search_best_adc` 那 175 行几乎是从建模函数里抄过来的。它们本该产生完全相同的结果，但只要有一处笔误，搜索出来的「最优分角」就和实际建的模型对不上——而且这种错误不会报错，只会静默地给你一个不太均匀的网壳。

### 拆成四层

重构后按职责分成四层，从下往上谁也不认识谁：

```
vec helpers            向量运算原语（纯函数）
    ↓
ShellGeometry          纯几何：节点坐标 + 杆件拓扑，不 import 任何 CAE 库
    ↓
search_best_adjustment 用 ShellGeometry 搜最优系数
    ↓
GeodesicShellPart      把几何结果落地成 Abaqus Part
```

关键约束是第三层只依赖第二层。`ShellGeometry` 里没有一个 `mdb`、没有一个 `abaqus` 字样。

### 三个具体手法

**1. 几何只算一遍。** `search_best_adjustment` 从 175 行变成 14 行：

```python
def search_best_adjustment(f1, f2, span, rise, candidates=None):
    if candidates is None:
        candidates = [i / 100.0 for i in range(-2, 13)]
    best_adj, best_var = 0.0, float('inf')
    for adj in candidates:
        geom = ShellGeometry(f1, f2, span, rise, adj)
        var = _variance(geom.bar_lengths())
        if var < best_var:
            best_var, best_adj = var, adj
    return best_adj
```

因为它不再自己算几何，只是「构造 15 个实例，取杆长方差最小的那个」。

**2. 用回调注入差异，一份拓扑服务两种用途。** 这是整个重构里最值的一招。几何类发射杆件时走一个统一的出口：

```python
@staticmethod
def _emit(out, connect_only, connect, a, b):
    if connect_only:
        connect(a, b)        # 建模模式：连成线单元
    else:
        out.append(distance(a, b))   # 搜索模式：只记长度
```

于是搜索时传 `out=lengths`，建模时传一个 `connect=WirePolyLine` 的 lambda。**同一份拓扑代码，两种消费方式**——从根源上保证「优化的杆长」和「最终建出的几何」绝对一致。

Abaqus 和 SAP2000 两个版本也是靠这个派生的，换一个 `AddByCoord` 的 lambda 就行。

**3. 构造参数而非可变状态。** `adjustment` 通过 `__init__` 注入，不作为对象状态被反复重设：

```python
def __init__(self, f1, f2, span, rise, adjustment):
    ...
    self.radius = rise / 2.0 + (span * span / 8.0) / rise
    self.z_angle = math.acos((self.radius - rise) / self.radius)
    base_split = f1 / float(f1 + f2)
    self.z_angle_upper = (base_split + adjustment) * self.z_angle
```

一个实例 = 一组确定的几何。这样「搜索」就退化成了「构造一系列干净的新实例取最优」，不用去操心对象被改脏了。

### 顺手修掉的几个坑

- **零向量 bug**：原 `xyz_coordinates` 在 `x=y=0` 时角度未定义，靠「那条分支从不被触达」苟活。新写法就是把点缩放到半径 r，没有分支可错。
- **`pi` 未定义**：原文件用了 `pi` 却只 `import math`，同样是靠分支不可达在蒙混。
- **Abaqus 内嵌 Python 的生成器不兼容**：`sum()` 传生成器表达式会抛 `TypeError: arg1; found 'generator'`，必须换成列表推导。这个只能踩出来，文档里没有。
- **Python 2 的整型除法隐患**：补上 `from __future__ import division`。
