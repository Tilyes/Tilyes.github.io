# 为什么我把个人主页搬到了 GitHub Pages

之前折腾过不少方案：买域名、租服务器、装 WordPress、配 Nginx、申请备案……最后发现我其实只是想要一个**能写点东西、能被搜到的地方**。

GitHub Pages 刚好满足这个需求，而且几乎什么都不用管。

## 它解决了什么问题

| 方案 | 成本 | 维护 | 麻烦程度 |
| --- | --- | --- | --- |
| 自建服务器 | 每月几十到几百 | 需要自己打补丁 | 高 |
| 建站平台 | 通常带广告或收费 | 平台说了算 | 中 |
| GitHub Pages | 免费 | 提交即发布 | 低 |

对一个个人主页来说，第三行的优势太明显了：

- 仓库就是备份，本地永远有一份完整内容
- `git log` 天然是修改历史，改坏了直接回滚
- 想换域名，加个 `CNAME` 文件就行

## 代价是什么

也不是没有短板，说几个真实的：

1. **国内访问速度一般**。没有 CDN 加速时偶尔会慢，介意的话可以套一层 Cloudflare。
2. **只能放静态内容**。想做评论、搜索、登录，得接第三方服务。
3. **构建有上限**。Jekyll 跑太慢会被限制，不过纯静态页面根本不触发这个限制。

> 我的结论：如果你要的是"一个长期存在、内容归自己所有的页面"，GitHub Pages 几乎是当前最优解。

## 我最后选的形态

把复杂度压到最低——纯 HTML + CSS + 一点原生 JS，不引入任何构建工具：

```
site/
├── index.html        首页
├── blog.html         文章列表
├── post.html         文章详情
├── assets/           样式、脚本、配置
└── posts/            Markdown 原文 + 索引
```

好处是**十年后打开还是能跑**。没有 Node 版本问题，没有依赖过期，没有 `npm install` 失败。

写文章 = 往 `posts/` 丢一个 `.md`，再在 `posts/index.json` 里登记一行。就这样。
